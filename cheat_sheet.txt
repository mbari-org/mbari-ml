mbariml Cheat Sheet
========================================
Regenerated for the unified `mbariml` CLI (v0.7.0). This walks through the
pipeline in order, with one working example command per step. The full,
authoritative --help output for every command is captured verbatim at the
bottom of this file -- if this walkthrough and --help ever disagree, trust
--help (it's generated straight from the code, not hand-maintained).

SETUP
-----
    pip install -e .
This installs the `mbariml` command (see pyproject.toml). Confirm it worked:
    mbariml --help
requirements.txt is also kept, for anyone who just wants
`pip install -r requirements.txt` without an editable install.

HOW TO READ A TYPER COMMAND (read this once)
---------------------------------------------
Every command has the shape:
    mbariml <command> [ARGUMENTS] [OPTIONS]

- ARGUMENTS are positional, required, and passed in order with no flag --
  e.g. in `mbariml detect models/best.pt /data/images/ /data/out/` the three
  paths are arguments, matched to model_path / image_dir / output_dir purely
  by position. Get the order right; there's no `--model-path=` form for
  these (they show as `{name}` in the Usage line and under "Arguments" in
  --help, not under "Options").
- OPTIONS start with `--` and go anywhere after the arguments. They're
  optional unless --help marks them `[required]`. Most also show a
  `[default: ...]` -- that's what happens if you omit the option entirely.
- Boolean options come as on/off pairs, e.g. `--force` / `--no-force` --
  pass whichever one you mean; the `[default: no-force]` etc. shown in
  --help is what you get if you pass neither.
- `--help` works on every command, including the bare `mbariml --help` for
  the full command list. Always available, always accurate.
- Nothing in this pipeline silently does nothing: a bad path or bad value
  raises immediately with a message, and unexpected failures print a full
  traceback and exit non-zero.

ORDER OF OPERATIONS
====================

STEP 1 -- detect
  Run YOLO over a directory of survey images (searched recursively), crop
  out every detection as an ROI, and seed a fresh curation database.

    mbariml detect models/best.pt /data/survey_images/ /data/survey_results/

  Produces: /data/survey_results/yolo_predictions.duckdb, names.txt
  Useful options: --limit N (quick test run, or right-size a real run --
  e.g. --limit 1000 out of 9000+ images), --random (with --limit, sample
  randomly across image_dir instead of taking the first N in sorted order --
  first-N on a chronologically-named survey is a contiguous time slice, not
  a representative sample), --seed N (reproducible --random sample),
  --device auto|mps|cuda|cpu

STEP 2 -- embed
  Compute a DINOv3 embedding for every ROI that doesn't have one yet. Three
  independent speed levers, all tuned automatically by default:
    --batch-size (default 32)      ROIs per GPU forward pass
    --decode-workers (default ~16) threads for CPU-side decode/preprocess
    --flush-size (default 2000)    embeddings applied per bulk DB UPDATE
  The last one matters most in practice -- DuckDB is dramatically slower at
  many small row-by-row UPDATEs than at one bulk UPDATE, and this is what
  actually caused a real run to grow from ~45 it/s to ~6.5 it/s and keep
  falling. With flush-size batching it holds a flat ~70-75 it/s instead.
  Safe to Ctrl-C and re-run any time: only rows with embedding IS NULL are
  processed, so nothing already done (i.e. already past a completed flush)
  gets redone.

    mbariml embed /data/survey_results/yolo_predictions.duckdb

  If a run is still far slower than expected with a confirmed MPS/CUDA
  device, check Activity Monitor / nvidia-smi for something else competing
  for the GPU before assuming it's this code.

  If you ever change the embedding model, or the database already has
  embeddings from a different one, recompute everything (never mix two
  models' embeddings in one database):

    mbariml embed /data/survey_results/yolo_predictions.duckdb --force

STEP 3 -- cluster
  Cluster embeddings with EVoC, tag each cluster with its dominant label,
  and write review grids (JPEGs of many ROIs at once) to roi_grids/. Logs
  progress at each phase (fetching, building the matrix, clustering,
  writing results) so a long run is never silent. The clustering itself is
  fast even at 300k+ points (evoc has its own built-in approximate nearest-
  neighbor search, not brute-force KNN -- DuckDB VSS/ANN wouldn't help
  here); a slow run in practice means the database write, which is now a
  single bulk UPDATE instead of one per row.

    mbariml cluster /data/survey_results/yolo_predictions.duckdb

  EVoC's real tuning knobs are exposed if the default separation doesn't
  look right -- e.g. clearly distinct things ending up in "noise":
    --approx-n-clusters N   target cluster count [default: 18] -- raise this
                            (or pass 0 to let EVoC choose) if you expect more
                            than 18 distinct visual groups
    --noise-level F         0.0-1.0, EVoC's main noise/outlier-sensitivity
                            knob [default: 0.2] -- lower calls fewer points
                            noise (at some cost to cluster accuracy)
    --base-min-cluster-size, --n-neighbors, --min-samples, --seed
  See `mbariml cluster --help` for what each one actually does.

STEP 4 -- refine (optional)
  Re-cluster one label's ROIs into finer sub-clusters -- useful when step 3
  lumped something too coarsely (a big catch-all "noise" cluster, etc.).
  Takes the same EVoC tuning knobs as step 3 (own defaults, since it's
  usually re-clustering a much smaller subset) -- e.g. --noise-level 0.3 to
  dig harder for structure inside a big noise bucket.

    mbariml refine /data/survey_results/yolo_predictions.duckdb /data/survey_results/ --new-label noise

STEP 5 -- review (interactive GUI)
  Label and delete ROIs by hand.

    mbariml review /data/survey_results/yolo_predictions.duckdb

  Start filtered to one label:

    mbariml review /data/survey_results/yolo_predictions.duckdb --label noise

  In the grid: click a thumbnail to select it, Shift-click for a range,
  Ctrl/Cmd-click to add to the selection; arrow keys navigate/extend a
  selection too. Press 1-9 to instantly apply one of the 9 most-used labels
  (also shown as buttons); type a label and press Enter to apply something
  new/rare; right-click an ROI to sort every page by embedding similarity to
  it (needs step 2 to have run); Delete removes the selection (asks first --
  it's permanent); Escape clears it. A tile-size slider and "hide
  labeled"/"hide unlabeled" checkboxes control what the grid shows. The
  status bar shows progress while a page loads or a similarity sort runs,
  and always shows "Page X/Y" -- a "Go to page" spinbox next to
  Previous/Next jumps straight to any page.

  "Show label" toggles what each tile/box displays: "New Label" (the
  curated new_label -- blank for everything until `mbariml cluster`/manual
  review sets it) or "Original Label" (the raw YOLO class from `detect`,
  always present). Reviewing raw detections before ever clustering? Switch
  to "Original Label" so tiles aren't blank. Purely a display choice --
  filtering, sorting, and quick-label writes always target new_label
  either way.

  The right-hand panel shows the full source image with mouse-wheel zoom and
  click-drag pan (not just a static preview), and overlays *every* detection
  on that image as a box -- not just the current page's rows, since other
  detections on the same frame can be sorted onto a different page. Drag a
  box's handles to resize/reposition it (saved immediately, and the crop
  stored in the database is regenerated to match); the box for whatever's
  currently selected shows green, the rest pale blue-grey; right-click a box
  for "Delete". A single image with hundreds of detections caps the boxes
  shown (an image's own status line says so) to keep this responsive.

STEP 6 -- export-voc
  Export curated labels (new_label, excluding "noise") as Pascal VOC XML,
  plus a new_names.txt list of every distinct label used.

    mbariml export-voc /data/survey_results/yolo_predictions.duckdb /data/survey_results/

STEP 7 -- html
  Generate a paginated HTML gallery of images and their labeled crops --
  handy for a quick visual QA pass in a browser.

    mbariml html /data/survey_results/yolo_predictions.duckdb /data/survey_results/html

STEP 8 -- query (as needed, any time)
  Run any SQL you want against the database -- spot checks, counts, etc.

    mbariml query /data/survey_results/yolo_predictions.duckdb "SELECT new_label, COUNT(*) FROM predictions GROUP BY 1 ORDER BY 2 DESC"

STEP 9 -- infer-images (standalone -- START HERE for a new survey + a trained model)
  Run an already-trained model over a brand new batch of images. Doesn't
  need any earlier step's database to run -- but writes the SAME schema as
  every other step (yolo_predictions.duckdb, with ROI crops), so you can
  immediately continue into review/embed/cluster/export on its output too.

    mbariml infer-images models/best.pt /data/new_survey/ /data/new_survey_results/ --export-csv

  Then, straight from that output, with no need to run detect at all:

    mbariml review /data/new_survey_results/yolo_predictions.duckdb
    mbariml html /data/new_survey_results/yolo_predictions.duckdb /data/new_survey_results/html
    mbariml embed /data/new_survey_results/yolo_predictions.duckdb

STEP 10 -- remap-labels (as needed)
  Bulk-rename new_label values from a two-column CSV (old_label,new_label
  per row, no header).

    mbariml remap-labels /data/survey_results/yolo_predictions.duckdb changes.csv

UTILITIES (not numbered steps, run them whenever needed)
===========================================================

backfill-sharpness -- compute real sharpness (blur) scores for a database
  created before step 1 started doing that automatically. Needed once
  before "Sort by Sharpness" in the review GUI means anything for an older
  database:

    mbariml backfill-sharpness /data/survey_results/yolo_predictions.duckdb

export-ids -- write a *.id sidecar file next to each source image that has
  at least one curated identification (new_label set, not "noise"), wherever
  that image actually lives on disk. Header records the model, who ran it,
  and when; each identification is a 4-vertex pixel polygon with lon/lat/
  depth left as 0.0 placeholders for a later navigation-merge step:

    mbariml export-ids /data/survey_results/yolo_predictions.duckdb

SHORTCUT: RUN THE WHOLE CHAIN AT ONCE
========================================
`mbariml run` chains detect -> embed -> cluster -> export-voc -> html against
one database:

    mbariml run models/best.pt /data/survey_images/ /data/survey_results/

Start or stop partway through with --from-step/--to-step (one of 1, 2, 3, 6,
7) -- e.g. to resume after reviewing in the GUI and just re-export:

    mbariml run models/best.pt /data/survey_images/ /data/survey_results/ --from-step 6 --to-step 7

--random/--seed (step 1 image sampling) and --approx-n-clusters/--noise-level
(step 3 clustering) pass through too, sharing one --seed for a fully
reproducible run:

    mbariml run models/best.pt /data/survey_images/ /data/survey_results/ --limit 1000 --random --seed 42

For every other EVoC knob (--base-min-cluster-size, --n-neighbors,
--min-samples), run `mbariml cluster` directly instead of `mbariml run`.

Step 5 (review) and step 8 (query) aren't part of this chain since they
aren't batch operations. Step 9 (infer-images) and step 10 (remap-labels) aren't
either, since they don't chain against the same database -- run those
directly with their own subcommand.

mbariml infer-images --help

                                                                                                      
 Usage: mbariml infer-images [OPTIONS] {model_path} {input_dir} {output_dir}                          
                                                                                                      
 Run YOLO inference over every image under INPUT_DIR and store detections (with ROI crops, ready for  
 review/clustering/export) in OUTPUT_DIR/yolo_predictions.duckdb.                                     
                                                                                                      
╭─ Arguments ────────────────────────────────────────────────────────────────────────────────────────╮
│ *    model_path      <str>  Path to a YOLO .pt model, or a stock Ultralytics model name.           │
│                             [required]                                                             │
│ *    input_dir       <str>  Directory containing input images (searched recursively). [required]   │
│ *    output_dir      <str>  Directory to save the database, annotated images, and (optionally) a   │
│                             CSV.                                                                   │
│                             [required]                                                             │
╰────────────────────────────────────────────────────────────────────────────────────────────────────╯
╭─ Options ──────────────────────────────────────────────────────────────────────────────────────────╮
│ --export-csv    --no-export-csv             Also export a taxa-by-image count matrix to            │
│                                             predictions.csv.                                       │
│                                             [default: no-export-csv]                               │
│ --limit                            <int>    Limit the number of images processed (for a quick test │
│                                             run).                                                  │
│ --batch-size                       <int>    Number of images sent to YOLO per batch. [default: 50] │
│ --conf                             <float>  Confidence threshold. [default: 0.08]                  │
│ --iou                              <float>  IoU threshold for NMS. [default: 0.15]                 │
│ --max-det                          <int>    Maximum detections per image. [default: 500]           │
│ --imgsz                            <int>    Inference image size. [default: 992]                   │
│ --device                           <str>    Device to run on: 'auto', 'mps', 'cuda', or 'cpu'.     │
│                                             [default: auto]                                        │
│ --help                                      Show this message and exit.                            │
╰────────────────────────────────────────────────────────────────────────────────────────────────────╯

mbariml run --help

                                                                                                      
 Usage: mbariml run [OPTIONS] {model_path} {image_dir} {output_dir}                                   
                                                                                                      
 Run the scriptable curation chain (detect -> embed -> cluster -> export-voc -> html).                
                                                                                                      
 Every step reads/writes OUTPUT_DIR/yolo_predictions.duckdb, so re-running                            
 with --from-step > 1 resumes against whatever is already in that database                            
 -- nothing upstream is re-run or overwritten.                                                        
                                                                                                      
╭─ Arguments ────────────────────────────────────────────────────────────────────────────────────────╮
│ *    model_path      <str>  Path to the YOLO model (used by the detect step). [required]           │
│ *    image_dir       <str>  Directory containing input images. [required]                          │
│ *    output_dir      <str>  Directory for the database and all step outputs. [required]            │
╰────────────────────────────────────────────────────────────────────────────────────────────────────╯
╭─ Options ──────────────────────────────────────────────────────────────────────────────────────────╮
│ --from-step                           <int>    First step to run: one of 1, 2, 3, 6, 7.            │
│                                                [default: 1]                                        │
│ --to-step                             <int>    Last step to run (inclusive): one of 1, 2, 3, 6, 7. │
│                                                [default: 7]                                        │
│ --limit                               <int>    Limit passed through to steps that support it, for  │
│                                                a quick test run.                                   │
│ --random               --no-random             With --limit, sample images randomly (step 1)       │
│                                                instead of taking the first N in sorted order.      │
│                                                [default: no-random]                                │
│ --seed                                <int>    Random seed, shared by --random image sampling      │
│                                                (step 1) and EVoC clustering (step 3), for a        │
│                                                reproducible run.                                   │
│ --approx-n-clusters                   <int>    Passed through to step 3; see `mbariml cluster      │
│                                                --help`.                                            │
│                                                [default: 18]                                       │
│ --noise-level                         <float>  Passed through to step 3; see `mbariml cluster      │
│                                                --help`.                                            │
│                                                [default: 0.2]                                      │
│ --help                                         Show this message and exit.                         │
╰────────────────────────────────────────────────────────────────────────────────────────────────────╯
